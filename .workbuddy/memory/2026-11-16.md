## 1. 算路请求快照化（`src/ui/window.{h,c}`、`src/route/route.c`）

- **根因**：算路 5 秒级，期间 UI 线程照样能加点/删点/改偏好，worker 直接读
  `App.pick_a / via[] / pref_*` ⇒ torn read。最典型是途经点：worker 先读 `n_via`
  再按它遍历 `via[]`，两步之间用户删了一个点，就按新 `n_via` 读旧数组（坐标错位）。
- **修法**：`NavReq` 完整快照（起终点 / 途经点 / 偏好 / 出行方式），**提交时由主线程
  一次做好**，worker 只吃快照。`Router` 的惰性创建与偏好下发收进 worker
  （`nav_router_configure`），主线程连 `router_set_prefs` 都不许调；唯一例外是
  UI 线程同步入口（`app_nav_plan_sync` / `app_gpx_snap`）先 `nav_router_acquire_sync`
  等 worker 空闲。途经点段里程改由 `NavResult.via_seg_km` 搬回，worker 不写 `App`。
- **为什么不用锁**：锁只能保证"读到某一刻的值"，不能保证"读到的一组值互相自洽"；
  快照把一致性做在提交点，后续 UI 怎么改都不影响已提交的这一单。

## 2. PBF 显示层三处泄漏（`mapset.c`、`pbfmap.c`、`dmap_selftest.c`）

一省显示层是三块手 `malloc`（`lines`/`areas`/`polyrefs`，`mapped=0`），不在 mmap，
也不归 `nmbin_close`——

| 出口 | 旧代码 | 实测泄漏 |
|---|---|---|
| `dmap_worker` 让出 | `if (!ok) pbfmap_free(&m)`（**条件写反**） | mongolia **44.8 MB** |
| `mapset_free` | 只 `destroy` 锁，不看 `job_result` | 已解完未 publish 就退出 |
| `src_close` | 只 `nmbin_close` + `memset`，不碰 `s->dmap` | macau **1.1 MB** |

- **修法**：`pbfmap.c` 按 `data_len` 配平字节账（`memfile_finish` 加、`pbfmap_free` 减，
  `__atomic` 跨线程），导出 `pbfmap_live_bytes()`；出口一律**无条件** `pbfmap_free`
  （幂等）；`src_close` 先 `pbfmap_free(&s->dmap)` 再 `memset`。
- **判据**（`dmap_selftest` 判据 6，两种姿势）：① 解码完成后退出 ② 解码途中退出，
  断言 `after == base`。旧行为实跑：`退出后多出 1.1 MB / 44.8 MB`、`DMAP-FAIL` rc=1。

## 3. Android 增量更新：提交原子化（新增 `AtomicCommit.java`）

- **四处**：`ChunkUpdater` 的数据文件与块表、`ChunkDelta.apply` 的 `.new`、
  `verifyAndCommit` 的整包。旧写法 `dest.delete()` → `tmp.renameTo(dest)`，两步之间被杀
  ⇒ 只剩 `xxx.new`、正式文件消失，而块表仍旧 ⇒ 下次按旧块表 patch 不存在的文件。
- **修法**：`AtomicCommit.commit(tmp,dest)` = 查 `tmp.isFile()` → `fsync` 文件 →
  `Files.move(REPLACE_EXISTING, ATOMIC_MOVE)` → `fsync` 目录；**数据先、块表最后**；
  `cleanStaleTemps` 清残留；`discard()` 幂等删临时。
- **判据 4 条**：`COMMIT-INJECT-CAUGHT` / `COMMIT-ATOMIC-OK` / `COMMIT-RECOVER-OK` /
  `COMMIT-PATH-OK`（结构判据：源码出现 `File.renameTo` 即失败）。
- 对照：把 `verifyAndCommit` 改回旧写法 ⇒ `ASSERT-FAIL 临时文件缺失时旧文件必须原样保留`。

## 4. Android 下载器：实收字节数（`Downloader.java`、`DownloadActivity.java`）

- **根因**：只有 sha256 一道闸，而**哈希可以缺席**（老服务端清单无 `sha256`）⇒
  `verified=false` 却照样落盘，截断 zip 被当成功。
- **修法**：三道闸（空包 / `part.length()!=read` / `read!=expect`，`expect` 优先清单
  `size` 再退回 `getContentLengthLong()`）+ 中途异常删 `.part`；`Row.size` 接线到调用。
- **判据**：`SIZE-INJECT-CAUGHT`（清单 7500 实收 5000 / 200+0 字节 / 服务端谎报 7500 实发 5000
  各必拒，**如实声明 5000 必放行**）。对照：三道闸改 `if (false && …)` ⇒ 第一条即挂。

## 6. 本轮踩的坑（可复用）

- **结构判据会被自己的注释误伤**：`COMMIT-PATH-OK` 第一版扫到 javadoc 里贴的旧代码
  `tmp.renameTo(dest)` 直接失败 ⇒ 扫描要跳过 `*` / `//` 注释行。
- **`HttpExchange.close()` 不声明受检异常** ⇒ `catch (IOException)` 不可达，编译报
  「异常从未在 try 体中抛出」。写夹具时别按直觉加 try。
- **`Files.move` 撞非空目录抛 `DirectoryNotEmptyException`** ⇒ 这是"让块表现在写入失败"
  最省事的注入手段（把 `chunks.json.new` 做成非空目录）。
- **判据用绝对值会被外层污染**：`leak_case` 必须以调用前的活字节为基线（外层 `MapSet`
  自己的缓冲凭空多 1.1 MB）；判据 5 收尾**回省**会再派发一次解码，把判据 6 基线打脏。
- **判据 kind=1 的 `before-base` 可能 0.0 MB**（在途快照还没产出），真正判据是
  `after == base`，输出里的「本例占 X MB」只是参考。
- **PowerShell 不支持 heredoc**（`python - <<'PY'` 直接 ParserError）⇒ 批量改文件用
  `replace_in_file` 或临时脚本文件。
- **长命令被后台化时输出会丢**：结论一律以落盘日志（`> build_rel/_x.log`）为准。
- `skedaddlegui.exe` 曾被打断成 0 字节，需单独重链（6.55 MB 才是好的）。
