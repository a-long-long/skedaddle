## 启动后探测系统语言并询问切换（新增功能）
- 需求：运行后先查系统区域/语言，与当前 `lang` 设置不一致且本 app 支持时，弹窗让用户决定是否切换。
- 实现：`MainWindow::checkSystemLanguage()`，挂到 `start()` 末尾 `QTimer::singleShot(0, this, ...)`（事件循环起来后再弹，不阻塞 `start` 返回）。
  - **为何挂 start()**：`--ui-test` 与 `--shot` 分支都不调用 `start()`（qt_main.cpp 提前 return），故无头模式**绝不**弹窗卡住——已用 `--ui-test` 验证 EXIT=0、QT-UI-OK 无回归。
  - 探测用 `QLocale::system()`（跨平台，不碰 `#ifdef _WIN32`），映射：Chinese→I18N_ZH、English→I18N_EN、其它→跳过（暂无翻译，不弹）。
  - 提示文案用"目标语言"本身书写（英文系统看到英文提示），含 `QLocale::system().nativeLanguageName()`（如 "English (United States)"）展示区域。
  - 用户决定后写 `lang_autodetect=1`（直接 settings key，与 `lang` 同一持久化路线：`settings_set_int` + `app_persist_settings`），之后不再打扰。该 key 不进 `SETTINGS_SCHEMA`（纯内部标记，避免出现在设置面板）。
- 验证：构建零警告；`--ui-test` 全过；独立 Qt 小程复刻映射逻辑——English→EN、Chinese→ZH、Japanese/German/French→skip，本机实测 `中文(简体)/中国`。
- **设计取舍（待 J 先生确认）**：当前为"首次不一致时询问一次，记录决定后不再提示"（避免每次启动都打扰）。若他要"每次启动都检查并弹窗"，去掉 `lang_autodetect` 短路即可。

## 语言文件改为运行时外部 XML（本次，WIP 提交 5513504）
- J 先生要求"每种语言单独作成一个语言文件"，先选了运行期外部文件，后改口要 **XML**。最终落点：每种目标语言一个独立 XML（`lang/en.xml`，简化 TS 风格 `<item><zh>中文</zh><en>English</en></item>`）。
- 中文是源语言（msgid），内联在代码，**不**生成文件。
- 加载机制：`i18n_set_lang_dir(const char *dir)`（Qt 侧在 `MainWindow` 构造里用 `QApplication::applicationDirPath()+"/lang"` 传入）→ `i18n_set_lang` 时按 `<code>.xml` 加载到动态 `g_pairs`；**文件优先，内置 `TR[]` 兜底**（文件缺失/损坏时英文模式仍可用，零回归风险）。
- `i18n.c` 自写极简 XML 解析：实体 `&amp; &lt; &gt; &quot; &#NNN; &#xHH;` 还原 + 字面 `\n \t \\ \"` 兼容；含换行串在 XML 里用真实换行保存（`export_lang.py` 把 i18n.c 源码里的字面 `\n` 还原成真实换行）。
- 新增 `scripts/export_lang.py`：从 `i18n.c` 的 `TR[]` 自动导出 `lang/en.xml`（351 条，与内置表同源）；手改 xml 会在运行时覆盖内置翻译。
- CMake：`skedaddle` 的 `POST_BUILD` 把 `lang/en.xml` 拷贝到 exe 同级 `lang/`。
- **构建修复（2026-11-01 验证补全）**：
  1. `i18n.c` 漏写 `g_pairs/g_n/g_lang_dir` 前向声明——三者原在文件末尾定义，但 `i18n_set_lang`（第 11 行）就引用 `g_n/g_pairs`，导致 `undeclared`。已把 `TrPair` typedef + 三个全局变量上移到文件顶部（`i18n_load` 前向声明之后）。
  2. `skedaddle` 原先 `target_link_libraries(... navmap_core ...)`，而 `navmap_core` 仅含 `core_anchor.c` 的**空壳**、并未聚合子模块库；CMake 还把它展开成 `-lnavmap_core` 且 `LINK_PATH` 缺 build 目录 → 链接失败 `cannot find -lnavmap_core`。改为直接链子模块库（与 `nm_link_tool` 同款：`navmap_pbf geo strpool plat mem map search route render ui settings i18n` + `${ZLIB/SQLITE3/PROTOC/NM_LEAF_SYS_LIBS}`），CMake 展开成相对路径 `libnavmap_*.a` 在 build 目录下可正确解析。`-I src` 那行仍保留。
- **验证全绿（2026-11-01）**：`NM_CC_RETRY=0 cmake --build build --target skedaddle` 零警告(-Werror)链接成功；POST_BUILD 把 `lang/en.xml`(351 条) 拷到 `build/lang/`；`--ui-test` EXIT=0/QT-UI-OK、中文断言全过（含下载树 beijing 判定/selectByLeaf 命中）；独立程序链 `libnavmap_i18n.a` 切 EN：`北京→Beijing`、含换行 key 查到英文、未知 key 回退中文；**用临时覆盖 XML 证伪"XML 优先于内置 TR[]"（`北京` 返回覆盖值 Beijing_XML_OVERRIDE）且 XML 缺失条目回退内置 TR[]**。外部 XML 语言文件链路端到端打通。
