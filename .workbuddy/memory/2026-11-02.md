## PBF 运行时解码（`--pbf-display`）存留评估（2026-11-02 用户问「还需要吗」）

**结论：作为默认路径不需要（生产默认关闭、tile 全面胜出）；但别急着删——它有唯一独家价值「省磁盘」。**

### 它的定位与代价（全部实测）
- 引入于 `2436526`(10-23)，目的**不是性能**，是**让 lines/areas/polyrefs.bin 三个文件整个不落盘**。
- 数据保真：`pbfmap_check` 逐字节 IDENTICAL；出图 md5 与整省**完全相同**（比 tile 还忠实）。
- 代价：北京首次解码 **1.75~1.80 s**（tile 179~210 ms，慢 9.8 倍）；峰值 RSS 曾实测天津 104 /
  北京 275 / 河北 714 MB。
- ★★ **致命限制：它依赖 `nodes.bin`**（`mapset_ensure_display` 里 `if (!s->loaded) return -1;`
  + `pbfmap_decode(pbf, &s->nodes, ...)` 用 osm_id 二分查表拿内部下标）⇒ **不能**用于
  "只有新 pbf、还没抽取产物"的应急显示场景。它省的是 3 个文件，不是全部产物。

### 磁盘账（8 省实测）
| 方案 | 显示层落盘 | 首次进省 |
|---|---|---|
| 整省三件套（无 tile） | 195.0 MB | ~0 ms |
| 整省 + tile（=当前） | 195.0 + 221.1 MB | ~0 / 0.05 ms |
| 仅 tile | 221.1 MB | 18.8 ms |
| **仅 PBF 解码（不写 tile 不写三件套）** | **0 MB** | **1750 ms** |

- tile 比整省**多占 13.4%**（跨边界重复）：beijing +13.7% / henan +45.5% / shanxi +47.2% /
  shandong −21.8%（唯一变小的省）。
- ⇒ 「省磁盘」这个价值**已被更好的方案压制**：若真要省，改 `graph_build` 只写 tile、不写整省三件套，
  能省 195 MB 且只付 18.8 ms；比 PBF 解码（省 221 MB 但付 1750 ms）划算得多。
- ⇒ PBF 解码只在**极端零磁盘部署**（显示层完全不落盘）才有独占场景。
