### 第四批：车头朝上引导视角（rot 从装饰角度升级为每帧导航视角）

**投影层（src/map/map_view.c）**——原先只有 `mv_proj`/`mv_unproject` 认 rot，其余 4 个接口都假设「屏幕 y ↔ 纬度单调」：
- `mv_init()` 显式清 `rot=0` / `c_valid=0`（复用 MapView 时不残留）。
- `mv_visible_bbox()`：rot!=0 时反投影**四个屏幕角**取 min/max（轴对齐超集）；rot=0 保留原「左下+右上两角」算式逐位不变。两角口径会把 bbox 算小 ⇒ `paint_areas/paint_lines` 的地理裁剪整块剔掉要素。
- 抽出 `screen_to_world_vec()` = R(+rot)，供 `mv_pan_pixels()` / `mv_zoom_at()` 共用：拖动方向、滚轮锚点在旋转下不再漂。
- `mv_fit_bbox()`：rot!=0 时把世界 bbox 四角按 R(-rot) 转到屏幕空间取跨度（45° 时旧算法差 √2 倍）。
- ★ rot=0 分支算式保持原样（`-dx/s` 与 `+(-dx)/s` 在 IEEE 下逐位相同），已用发布包 exe 对拍验证。

**渲染层**
- `paint_nav_car()`：屏幕角 = `heading_deg - v->rot`，`rot==heading` 时车标恒指屏幕上方。
- `paint_areas_banded()` / `paint_lines_banded()` 加 `if (ctx->P->rot != 0.0) return -1;` → 落回串行，与 `paint_roads_banded` 已有的 rot guard 同纪律（旋转下 bbox 两角的屏幕 y 不再包住整个要素）。导航视角 z15 串行本就够快。
- 指北针符号反号修正：正投影是 R(-rot)，北向 (0,-R) 落在 `(-R·sin rot, -R·cos rot)`；`chrome.c` 与 `ui_qt/map_canvas.cpp` 原写成 `+R·sin rot`（rot=90 时本该指左却指右）。
- 互斥：点指北针 / 手动 Ctrl+拖动旋转时同时清 `heading_up` 和 `rot_from_heading`，否则下一帧航向又把 rot 写回去。
- 真实 GNSS：`heading_up && ext_valid && !sim_on` 时 `view.rot = ext_course`（NMEA 方位角，与 sim.heading_deg 同口径）。
- 离屏验收入口：`--rot=<度>` 加进 `offscreen_shot.c` **和** `qt_main.cpp` 的参数白名单（漏了后者会报「未知参数」）；`--rot=0` 即负向对照锚点。

**新增工具 `tools/mapview_selftest.c`（MAPVIEW-OK）**
